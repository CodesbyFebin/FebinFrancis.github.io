Three.js and WebGL: 3D Graphics on the Web

Complete guide to Three.js and WebGL for web graphics. Covers scene management, materials, lighting, shaders, and optimization techniques for production 3D applications.

Published October 3, 2026 · Evidence-first technical note

Scope: This article explains engineering concepts and patterns. Repository source, tests and evidence remain authoritative for implementation claims.

Why this matters

WebGL brings GPU-accelerated 3D graphics to browsers. Three.js abstracts the complexity of WebGL, providing a scene graph, cameras, lights, and materials. Understanding both layers is essential for performance optimization and advanced graphics.

Three.js fundamentals

A scene contains:

  • Geometries: Vertex data (positions, normals, UVs).
  • Materials: How to render geometries (color, texture, lighting model).
  • Meshes: Geometry + material + position/rotation/scale.
  • Lights: Illuminate the scene (directional, point, spot, ambient).
  • Camera: Perspective to render from.
  • Renderer: Renders the scene to a canvas.

Lighting models

  • Ambient: Uniform light from all directions (no shadows).
  • Directional: Light from a direction (like sun); can cast shadows.
  • Point: Light from a position (like bulb); attenuates with distance.
  • Spot: Directional light with a cone of influence (like flashlight).

More lights = more expensive. Use ambient + one or two key lights for performance.

Materials

  • MeshBasicMaterial: Unlit; fast but no depth.
  • MeshLambertMaterial: Flat shading with diffuse lighting.
  • MeshPhongMaterial: Diffuse + specular highlights (plastic, metal appearance).
  • MeshStandardMaterial: Physically-based rendering (PBR); metallic + roughness parameters.
  • ShaderMaterial: Custom vertex/fragment shaders for advanced effects.

Textures and UVs

UV coordinates map a 2D texture onto a 3D surface. Import models with UVs already baked in; manually creating them is tedious. Texture loading is async; ensure textures load before rendering or use placeholders.

Performance optimization

  • Instancing: Render many copies of the same mesh with different transforms in one draw call.
  • LOD (Level of Detail): Use simpler models for distant objects.
  • Frustum culling: Skip rendering objects outside camera view.
  • Texture atlases: Pack multiple textures into one large texture.
  • Baking shadows: Pre-compute shadows as textures instead of rendering dynamically.
  • Vertex count: Fewer vertices = faster rendering. Simplify meshes where detail isn't visible.

Shaders (GLSL)

For advanced effects, write custom shaders:

  • Vertex shader: Runs per vertex; transform positions, compute lighting.
  • Fragment shader: Runs per pixel; compute final color.

Three.js provides uniforms (global values like camera matrix) and varyings (per-vertex data passed to fragment shader).

Camera controls

  • OrbitControls: Rotate around a point; good for object inspection.
  • FlyControls: Free movement in 3D space; like first-person camera.
  • PointerLockControls: Mouse-locked FPS camera.

Implementation checklist

  • Create scene, camera, renderer.
  • Add geometry, material, mesh.
  • Add lighting (at least ambient + one key light).
  • Use requestAnimationFrame to render each frame.
  • Implement camera controls.
  • Load textures asynchronously; use placeholders.
  • Profile rendering performance; optimize draw calls and vertex count.
  • Test on different hardware (mobile GPUs are slower).

Verification

Test rendering quality and performance:

  • Frame rate at various quality settings.
  • Lighting accuracy (compare to reference renderer).
  • Texture alignment and no obvious artifacts.
  • Performance on lower-end devices.
